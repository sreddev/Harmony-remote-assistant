How MyHarmony drives a Harmony 600

A teardown of the running Logitech MyHarmony 1.0.1.308 desktop app: what each layer does, which cloud services it calls, and the USB protocol it uses to read and write the remote.

Verified seen in binaries, files or the live system Inferred deduced from names and structure, not yet confirmed

The installed program is a browser shell plus a USB driver. Almost all logic, including the UI, the sync engine and the protocol scripts, is downloaded from Logitech at runtime as Silverlight packages. Without Logitech's servers the app cannot do anything.

JavaScript bridge

The page creates the USB plugin as <object id="HarmonyPlugin" type="application/x-harmonyplugin"> and stores it in the global remoteEngine. The Silverlight driver calls it through the browser bridge. It first checks for window.jsHandler. In this shell, jsHandler only offers clearCache, getAppVersion, getKeyBoardLocale, getKeyboardLayout and silverlightLoaded, so all device I/O goes to the plugin. Verified

HarmonyConfig.js also contains a WebSocket client that sends hbus commands to a Harmony Hub through the cloud. It is not used with a 600.

USB driver

Three native 32-bit DLLs in AppFiles\PlugIns\HarmonyRemoteDriver_32. They use the standard Windows HID driver, with no custom kernel driver.

Plugin callWhat it does
getDevices()Lists connected remotes with token, VID, PID, skin and report lengths.
addUsbDevice(vid, pid)Registers a VID/PID pair to watch for.
getAttributeByKey(key)Reads a plugin attribute, e.g. plugin_version.
performOperation(deviceId, packets, numberOfResponses)Sends HID packets and returns the responses. Every protocol step uses this.
cancelCommand(deviceId)Aborts the running command.
cleanupRemote(), cleanupAll()Releases handles.

SDE.dll holds the remote manager and HID channel classes. UsbDevice.dll exports OpenChannel, Read, Write, GetVendorId, GetProductId and the input/output packet sizes, and calls HidD_* plus DeviceIoControl. Verified

Molson protocol

The protocol family the driver's device table assigns to 046D:C122. It works like a tiny file system over HID.

The driver's config lists two Molson entries for this PID: model 96 (skins 91–96, "Martini") and model 66 (skins 66–75, "Member Web"). Both support five operations: identifyremote, connectivity, userconfiguration, learnir and firmwareupgrade. Which model your 600 reports is still to be confirmed.

Request packet

byte 00xFFservice ID
byte 1cmdcommand ID
byte 2seqsequence no.
byte 3nparam count
byte 4…paramsbyte, word, dword or string

Example: open the system info file is FF 01 00 02 "/sys/sysinfo" "R". The response echoes FF 01, carries the file handle at byte 5 and the file size (big-endian, 4 bytes) at byte 7. Packets are padded to the remote's report length. Verified

CmdNameUsed for
0x00PingCheck the remote responds. With one zero parameter it acts as a USB reset.
0x01OpenOpen a file: /sys/sysinfo, /ir/ir_cap, user config, firmware.
0x03WriteWrite user config or firmware data.
0x04ReadRead system properties or captured IR.
0x05FlushCommit a config or firmware update.
0x06DevCtrlStop IR learning, choose the checksum algorithm.
0x07CloseClose a file, leave learning mode.
0xFFResetReset the remote. Parameter 0x66 resets its file system.

From the template for model 96, architecture 16, and the other Molson templates. Verified

Template engine

Web.Driver.dll embeds about 230 XML "ROM" templates covering Logitech remotes from the Harmony 510 to the Ultimate One. Each template defines commandbuilder steps: the packets to send, how many responses to expect, values to check, and values to store (for example int:BE::file.size). Placeholders like %%remote.request.packet.length%% are filled in at runtime. The same engine also understands an older plain-HID protocol.

Sync flow

What happens when you press Sync.

sequenceDiagram
  participant U as You
  participant SL as Silverlight app
  participant API as Logitech cloud
  participant P as USB plugin
  participant R as Harmony 600
  U->>SL: Edit devices, activities, buttons
  SL->>API: Save calls (devices, activities, button maps)
  U->>SL: Press Sync
  SL->>API: ICompileManager.StartCompile
  API-->>SL: Compiled configuration
  SL->>API: IRomDataLibrary.RequestOperationData
  API-->>SL: Operation script and payload
  loop Each template step
    SL->>P: performOperation(deviceId, packets, n)
    P->>R: HID report (Open, Write, Flush, Close)
    R-->>P: Response
    P-->>SL: Response bytes
  end
  SL->>R: Reset
  SL->>API: IRemoteManager.RegisterSuccessfulSync

The order and the device-side commands match the templates. Exactly which call returns the config binary is Inferred and should be confirmed by watching a sync.

Learning IR

The reverse path: put the remote in learning mode, open /ir/ir_cap, read the captured signal, send it to IInfraredAnalysisManager.AnalyzeInfrared, then save the result as a device command. Inferred for the cloud step.

Risks

Cloud dependency

The app has no offline mode. If setup.myharmony.com or files.myharmony.com goes away, the remote can no longer be reconfigured with this software.

Old runtime

Chrome 29 from 2013 runs with the sandbox off and loads remote code, alongside Silverlight 5, which Microsoft no longer supports. Run the app only while you need it.

Open debug port

The DevTools port 127.0.0.1:8088 needs no password. Any program on the PC could control the signed-in session while the app is open.

The $ is not defined lines in console.log are harmless. InstallSoftware.js loads before jQuery.
